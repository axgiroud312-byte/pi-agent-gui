# 新开发计划：先原生底座，后 Pi 替换

依据：[产品目标](../product-goal.md)、[ADR 0001](../adr/0001-native-zcode-base.md)、主规格 #1。原 84 故事和 P/I/T 范围保持完整；以下阶段是顺序，不是首版裁剪。

## 阶段 0：原生导入与运行对照 — 复用 #32

1. 盘点当前仓库和所有 worktree，按 [旧成果清单](reuse-inventory.md) 固定来源提交。保留本仓库 Git 历史、开发文档和可复用模块。
2. 以固定 ZCode 完整公开源码建立新产品底座；先沿用其包管理、lockfile、Electron 入口、共享 UI/状态、构建资源和本地服务，不把旧自建框架覆盖上去。
3. 在隔离目录启动原版和产品副本，验证原生界面能真实操作。原 Agent 只用于明确标识的对照，不能声称 Pi 已接通。
4. 处理品牌及已确认的厂商专属入口；通用 provider/认证、分享、资源等保留目标和原生位置。保留源码和第三方许可/NOTICE。
5. 产出 [原生一致性验收](native-ui-parity.md) 所需成对截图、操作记录、入口差异表和可启动版本。

**完成界限：** 原生运行基线和可查看的产品副本真实可用，来源及修改清晰，技术检查通过，证据交到用户关卡。仅复制 CSS/独立展示组件不关闭 #32。

## 阶段 1：用户确认关卡 — #33

展示原版/产品对照与排除项。暂停，等待用户明确确认“原生界面与交互保留正确”。用户要求修改则回到 #32 修复；记录确认评论后才关闭关卡。

**关卡之前：** 可做原生导入、构建修复和基线取证；暂停所有 Pi 新适配和旧功能分支合并。不能把此次方向确认冒充未来实际界面确认。

## 阶段 2：原生服务接 Pi 的最小纵向闭环 — #34

保留 ZCode 原生会话 UI、状态订阅和操作入口，在 Agent/session service 边界映射到 Pi：

- 原生界面创建会话、发送文本、流式消息/一次工具运行、实际停止、读取/恢复原生历史。
- 将原生命令确认、snapshot/delta、session index、generation/cursor 与 Pi 真正状态映射；不把两种 stdio 协议当作相同。
- Pi 每会话运行隔离、JSONL framing、单写者、进程失败、不重放副作用等旧验证资产按需迁入。
- 原生前端队列只投影 Pi 队列；Pi 仍是 Agent loop/历史/工具/压缩权威。
- final product 的 Agent 请求没有原 ZCode Agent fallback；保留原版对照仅用于开发验收。

**完成界限：** 原生 ZCode GUI → 服务适配 → 真实 Pi 的链路可复现，功能和界面一致性同时验收，接口边界明确，审查/CI通过。之后开放依赖任务并行。

当前依赖：#33 原生阻塞于 #32；#34 原生阻塞于 #33；#3/#4/#5/#6/#7/#8/#14/#16 原生阻塞于 #34，其他能力票沿原依赖链汇入 #28。**当前只有 #32 是可领取的新路线实施前沿；#33 OPEN、ready-for-human，没有实际界面确认。**

## 阶段 3：复用现有实施票迁移全量能力

| 工作线 | Issues | 迁移原则 |
| --- | --- | --- |
| 完整对话、队列、并行工作台 | #3/#4/#5 | 使用原生输入框、时间线、队列及 pane 状态；映射 Pi 的真实运行和队列 |
| 树、认证、TUI、历史、配置、资源 | #6/#7/#8/#9/#10/#11/#12/#13/#25 | 复用已验证 Pi 模块，进入原生菜单/设置/详情/Side Pane，逐项登记必要差异 |

## 阶段 4：最终全量验收 — #28

在新原生工作台重新汇总每个 P/I/T 与用户故事的 Issue/PR/证据。执行真实模型文本/图片/文件工具/shell/停止/历史/扩展/provider/reload、OAuth/llama.cpp/MCP/GitHub/WSL/SSH，以及 Windows 安装/升级/回退/恢复。外部条件不足的项目保持开启。

只有原生用户关卡、全部必需能力、真实环境、审查、CI、发布文档和最终代码推送均满足，才能关闭 #1。

## 实施纪律

- Issues 和原生 blocking edges 为领取依据；`ready-for-agent` 不表示可越过尚未关闭的关卡。
- 先跑通原生工程，再根据实际 scripts 更新 CI；当前 npm 原型测试不是原生工程已启动的证据。
- 功能 PR 同时提交行为结果和界面对照；按 PR merge-base 审查所有提交。
- 接口稳定后才让 subagents 在独立分支/worktree并行；主 Agent 统一处理共享入口、依赖和集成回归。
- 普通技术问题自行解决。超出已确认范围的新增/删减或确需外部账户操作时，提出具体请求，并保留未完成状态。
