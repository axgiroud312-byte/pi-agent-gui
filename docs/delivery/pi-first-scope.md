## 保留的实现原则

Pi 是消息、工具、历史、运行状态、重试/压缩和队列的唯一事实来源。GUI 保留原生布局、组件、焦点、滚动和操作路径；在 Agent 服务边界做实际映射，内部接口可按需要精简。主会话继续使用固定 Pi JSONL RPC，公开扩展桥/宿主可补齐 RPC 不直接提供的认证、资源和树操作；“没有 RPC 命令”不是删除 Pi 能力的理由。

在线 provider、API key/OAuth、Pi 自带 `/llama`、Pi 包来源和主动分享仍属 Pi 使用范围。“不做远程开发”指 WSL/SSH 工作区等宿主能力，不指禁用模型网络访问。分享、bug 报告等外发必须由用户主动触发。

Pi 扩展加载和必要交互需要支持；复杂 TUI、自定义 renderer/header/footer/editor 等按固定公开接口逐类记录 GUI 等价、受限或不支持及原因。必要用户输入不能悬挂或假成功。不默认建设通用 TUI 兼容引擎，也不承诺任意第三方扩展零适配。#8 核实边界，#13/#25 实现必要交互。

## 退出首版的额外产品能力

不再默认建设完整 LSP/语言服务、通用多终端/后台命令平台、开发服务/端口/浏览器预览管理、完整 Git/GitHub/worktree 流程、内置 Plan/待办、子 Agent 编排、MCP 管理、WSL/SSH 和定时任务。

对应 #15–#24 共 10 张旧票标为“不计划实施”（wontfix / not_planned），保留正文快照、评论、源码和分支。#16 必要的 Pi shell/启动部分转由 #4/#10 承接；#17 必要文件预览由 #14 承接。退出范围不代表这些能力已经交付；现成原生组件可按需复用。用户安装扩展实现某业务，也不要求本项目另造对应系统。

取消四会话、完整 IDE 全入口、旧固定性能数量和云更新平台的强制要求。用两个真实会话检查隔离；长历史保留实际可用性验收。Windows 交付以可运行包为基础，若交付安装器则实际验证安装/升级/卸载。
