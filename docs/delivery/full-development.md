## 退出范围的任务

- #15：完整语言服务、全局搜索替换和诊断超出使用 Pi 所必需的桌面范围；文件引用与预览由 #14 承接。
- #16：不再单独建设多终端、ConPTY 管理或后台命令平台。Pi 原生 shell 与上下文语义由 #4 承接，必要启动参数由 #10 承接；已有终端可复用。
- #17：不再建设开发服务发现、端口和浏览器预览管理平台；必要的本地文件、图片和 Markdown 预览由 #14 承接。
- #18：完整 Git 状态、行级暂存、提交同步和冲突处理不是首版必需；已有只读信息与可复用组件保留。
- #19：GitHub Issue→worktree→PR 产品工作流不属于 Pi 核心能力或必要桌面体验。
- #20：不随附维护自有 Plan、待办和任务系统；Pi 扩展的加载、命令和交互由 #12/#13/#25 负责。
- #21：不建设自有子 Agent 编排系统；用户安装的 Pi 扩展按明确的扩展兼容范围使用。
- #22：不建设通用 MCP 管理系统；Pi 扩展可提供相关功能，不以此要求 GUI 另造 MCP 产品。
- #23：WSL/SSH 工作区、目标侧主管、远端 Git/PTY、端口转发和断线恢复退出首版；在线 provider/API/OAuth 仍由 #7/#10 保留。
- #24：不建设持久后台任务或定时调度平台；普通会话运行和保存恢复由 #4/#5 负责。

以上 10 票关闭原因为 not_planned，标签 wontfix；不能计为功能完成，也不再阻塞当前功能和 #28。历史依赖在快照中保留。

## 逐票执行与收口

1. 读最新父规格 #1、实施 Issue 正文/评论/前置、产品目标和复用清单；保留已有未提交工作，同目录只有一个源码写入者。
2. 以 Pi 真实语义为准复用 ZCode 原生组件，最小化接口适配；不引入第二套运行/队列/历史事实，不因实现困难伪装支持。
3. 按实际脚本跑相关本地检查。有 GUI/RPC/生命周期变更时验证原生 GUI→宿主→真实 Pi；在线账号、受控模型和安装器证据分开。
4. Standards/Spec 审查和必要界面对照通过后，记录具体提交、结果与限制；只有满足验收才关闭实施票。远程 CI 不作为任何关卡。
5. #28 逐项核对 [能力与场景账本](coverage.md)，交付对应最终源码的可启动 Windows 版本。停在用户验收；不继续扩展 IDE 或远程产品功能。
