## 产品定义

以 **ZCode 原生开源工程为产品底座**，保留它的界面组织和用户交互，在 Agent 服务边界接入 **Pi Coding Agent**。功能范围由 Pi 原生能力及必要桌面宿主能力决定；现成原生组件和操作路径用于承载这些能力，不自动要求补齐 ZCode 的功能全集。

原生交互一致性包括窗口与面板布局、工作区/任务/会话组织、标签/拖拽/分栏、Lexical 输入框、附件/引用/命令、消息与工具时间线、队列、菜单、设置、快捷键、焦点、滚动及状态反馈。仅复用颜色、字号、圆角或独立组件不满足目标。

## 原生工程与适配边界

原生 ZCode 前端不仅是 `packages/ui` 的样式层；它依赖工作台/会话状态、平台能力、服务访问器、会话订阅和命令确认协议。**保留的是页面布局、组件、交互、动态反馈、流式显示、工具卡、滚动、标签和分栏体验，不是旧 Agent 的内部架构。** 当前原生 v4 命令／订阅投影若是成本最低路径可以继续，但只保留前端需要且对应 Pi 真实事实的适配；旧接口没有 Pi 语义时显式不支持，不返回虚假成功或无效状态。Pi 唯一拥有消息、工具执行、历史、运行状态和队列，前端仅管理必要的展示与交互状态。更换 model provider 不等于更换 Agent。

原 ZCode Agent 仅可在隔离的原版对照阶段临时运行，用于建立真实交互记录。最终 Pi 产品的执行路径不得回退到原 Agent；前端继续需要的协议/类型/投影代码可保留，原引擎执行依赖应解除。

沿用上游锁定的构建体系建立可运行基线，再记录必要兼容调整。旧原型的 Electron/React/组件版本、npm 脚本和 assistant-ui 选择不约束新原生工程。Pi 版本与真实协议合同继续固定；IDE 领域仍区分工作区、会话、任务、运行和执行环境。

## 已允许的产品差异

1. 替换 ZCode 名称、Logo、产品标识和厂商推广文案；保留法律归属/许可证/NOTICE 中应保留的名称。
2. 移除 Z.AI/BigModel 产品账户、团队/充值/Coding Plan/专属配额、闲时票据等厂商商业入口。**Pi 本身支持的 provider/API-key/OAuth 登录仍保留**，使用原生设置结构呈现。
3. 厂商云分享/反馈/更新等服务不能直接作为本产品服务使用；Pi 原生分享、诊断和维护能力通过实际可用接口映射；外发由用户主动操作，不要求另建云服务或 GUI 自动更新平台。
4. Pi 包/资源及必要扩展交互保留映射目标；不默认开发通用 MCP 管理系统。文件、终端、预览等保留本地 Pi 使用所需或已可复用部分；完整 Git/GitHub、LSP、远程工作区等额外产品能力不再一并列为必需。
5. 公开 ZCode 中不可用的 Computer Use 占位不作为已交付能力，也不新增为首版要求。
6. Pi 真实语义与 ZCode 原语义存在冲突时，保持 Pi 事实，在原生交互结构内做最小调整，记录前后行为与原因。不得显示并不存在的审批、运行完成或工具能力。

具体入口、截图与处理结果记录在 [原生一致性验收](delivery/native-ui-parity.md)；每项排除都必须查明来源，不能把实现困难归为“Pi 不支持”。
