# 用 ZCode 原生工程承载 Pi，而不是重建相似界面

用户需要原生 ZCode 的布局和交互逻辑；旧方案以自建 Electron/shadcn/assistant-ui 工作台配合局部样式复用，虽验证了 Pi 协议，仍明显偏离目标。2026-09-22 经 grill-with-docs 确认：以固定 ZCode 原生工程为底座，保留 UI、状态及可复用宿主服务，在 Agent 服务边界映射 Pi RPC；放弃以旧自建前端或独立组件拼装作为产品起点。

代价是承接上游包结构、原生会话协议与必要服务适配，但可以直接保留布局、输入框、时间线、面板和操作路径。旧 Pi 模块/测试作为可选择迁入的资产；原生底座必须先有实际运行对照并通过一次用户界面确认，再进行 Pi 后端替换。完整能力范围保留，最终执行不得回退到 ZCode Agent；详细边界见 [产品目标](../product-goal.md)。
